# SOC Incident Investigation Report

## Incident ID
INC-2026-014

## Organization
TechCrush Financial Services

## Analyst
Victor

## Alert
ALERT-002 - Multiple Failed SSH Authentication Attempts

## Severity
Medium initially; elevated for investigation based on subsequent successful authentication.

## Executive Summary
The SOC identified repeated SSH authentication failures originating from an external source and targeting multiple accounts on the LINUX01 server. The activity was followed by a successful authentication to the alice account from the same source.

The available evidence indicates suspicious credential-based activity and potential account compromise. Additional investigation is required to determine whether the successful authentication was authorized.

## Affected Asset
LINUX01

## Source IP
203.0.113.50

## Target Account
alice (successful); root, admin (attempted, unsuccessful)

## Timeline
- 02:10:11 - Failed authentication attempt against alice
- 02:10:34 - Failed authentication targeting root
- 02:10:49 - Failed authentication targeting admin
- 02:11-02:13 - Repeated authentication failures across all three accounts
- 02:14:02 - Successful authentication as alice

## Evidence
- Linux SSH authentication log (evidence/alert-002.log)
- 14 failed authentication events confirmed via grep + wc -l
- Single consistent source IP confirmed via IP extraction and count
- Successful authentication event isolated and confirmed

## Assessment
The activity is suspicious and consistent with possible credential-based attack behavior: a single external source targeted three accounts in rapid succession before succeeding against one of them. However, the available evidence does not independently establish that the account was compromised. it does not yet confirm whether alice authorized this login herself.

## Recommended Actions
1. Validate the login with the account owner (alice).
2. Review authentication activity from 203.0.113.50 across other systems.
3. Review post-authentication activity on LINUX01.
4. Search other systems for the same source IP.
5. Review whether the alice account should remain active pending validation.
6. Escalate according to incident-response procedures if compromise is confirmed or strongly suspected.

## Conclusion
The alert requires continued investigation and appropriate escalation because repeated authentication failures were followed by successful access using a targeted account. This should not yet be classified as confirmed compromise.
